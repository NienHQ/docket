# Docket production plan

Audience: anyone (human or automated) picking up work in this repo cold.
Read this file, then [spec.md](spec.md) (the contract), then
[STATUS.md](STATUS.md) (what is done). Work through milestones in order;
tasks inside a milestone are independent unless a dependency is named.

## How to work on this repo

- **Spec first.** Behavior changes update docs/spec.md in the same change.
  The spec is the contract between modules; src/types.ts and src/schema.ts
  are its executable form. Do not change those three lightly, and never
  silently.
- **Verify:** `pnpm typecheck && pnpm vitest run && pnpm build`. All green
  before any commit. New behavior needs tests; fixed bugs need a regression
  test in tests/regressions.test.ts.
- **Determinism is a feature.** With no embedder configured, every public
  output must be reproducible byte for byte. No wall-clock inputs to
  scoring, no randomness, no iteration-order dependence. The e2e and
  regression suites enforce this; keep them passing.
- **Evidence is sacred.** Nothing may ever mutate a stored blob. Derived
  state must always be rebuildable from evidence via `reindex()`.
- **Style:** TypeScript strict (exactOptionalPropertyTypes,
  noUncheckedIndexedAccess), ESM with .js import suffixes, sparse comments
  (only non-obvious constraints). No em or en dash characters anywhere in
  repo content; use commas, colons, or parentheses. Commit messages are
  plain and authored by the repo owner; no tool attribution of any kind.
- **Fixtures:** tests/fixtures/corpus-small is generated by
  github.com/NienHQ/papertrail-bench (seed 7, 8 months, 2 vendors,
  1 customer, 12 questions). Regenerate only deliberately; tests read
  counts from its manifest.json but some name specific message files.

## Current state (2026-07-15)

v0.1 on main: all six layers work (evidence store, ingestion, index,
ledger, entities, tools + MCP). 48 tests including an e2e that answers
12/12 bench fixture questions with verified citations. Not yet published
to npm. No CI. Single-process, tested to a few hundred messages.

## Milestone 1: production hardening (do this first)

### 1.1 CI pipeline
GitHub Actions: typecheck, test, build on Node 20/22/24, ubuntu + macos
(better-sqlite3 is native; catching ABI breaks is the point). Add a job
that greps the tree for em/en dashes and fails on match. Badge in README.
Done when: PRs cannot merge red.

### 1.2 Incremental threading
`emlBytes` currently runs `rethreadAll()` per message and batch ingest
rethreads once; rethreadAll is O(all messages) each time. Add an
incremental JWZ update: a new message may only merge containers reachable
from its own id/references/subject key. Keep `rethreadAll()` as the
reindex fallback and as the oracle in a property test: for random ingest
orders of a fixture subset, incremental result must equal full recompute.
Done when: ingest of message N touches O(thread) rows, property test
passes, e2e unchanged.

### 1.3 Ingest at scale
Batch mode: wrap dir/mbox ingest in chunked transactions (e.g. 500
messages), defer indexing to one pass, report progress via an optional
callback. Add a perf harness (scripts/perf.ts, not vitest) that generates
a 3-year bench corpus (~15k messages) and reports ingest time, db size,
search latency p50/p95. Record numbers in docs/perf.md. Targets: 15k
messages ingested in minutes not hours on a laptop; search p95 under
100ms without embedder.
Done when: perf.md exists with reproducible numbers and the harness runs
in CI weekly (allowed to be slow, not allowed to crash).

### 1.4 Malformed input tolerance
Real archives contain garbage: truncated MIME, bad encodings, missing
headers, zero-byte parts, 100MB attachments. Ingest must never throw on
bad input in batch mode: quarantine instead (new `ingest_errors` table:
raw blob hash, error, at), continue the batch, surface counts in the
result. Add a fuzz-ish test: mutate fixture emails (truncate, splice,
re-encode) and assert no crash and full quarantine accounting.
Done when: `dir()` over a poisoned fixture completes with errors recorded
and clean messages fully ingested.

### 1.5 Concurrency contract
better-sqlite3 is synchronous, single process. Decide and enforce:
one writer, many readers. Set `busy_timeout`, document the contract in
spec.md section 2, make `Docket.open` take `{ readonly: true }` for
reader processes (MCP server should default to readonly unless facts
writes are wanted). Test: writer + two readonly opens operating
concurrently.
Done when: documented, tested, MCP server has a --readonly flag.

### 1.6 Schema migrations
`migrate()` currently only handles version 0 to 1. Introduce stepped
migrations (an array of (version, sql | fn)), a test that opens a v1
database file (committed fixture) and migrates it forward, and a rule in
this file: schema changes always add a migration, never edit old DDL.
Done when: the committed v1 fixture db opens correctly after the next
schema change lands.

### 1.7 npm release
Publish @nienhq/docket. Add: exports map check, `files` audit (dist only),
README install section, CHANGELOG.md (keep-a-changelog format), a release
script (version bump + tag + provenance publish via CI, npm trusted
publishing). Semver: 0.x, minor = breaking.
Done when: `pnpm add @nienhq/docket` works in a scratch project and the
MCP server runs from the installed package.

## Milestone 2: retrieval quality and real archives

### 2.1 Attachment parser interface + PDF text
Spec 3.3 promises pluggable parsing; today only text/* is indexed. Define
`AttachmentParser { mimes: string[]; parse(bytes): Promise<{ text,
pages?: spans }> }` in types.ts, wire into indexAttachment, ship a PDF
text extractor (pdfjs-dist or a lighter pure-JS extractor; must be
deterministic, no native deps). Parsed text is a derived artifact cached
by (blob hash, tool, tool version) per spec 3.3. OCR stays out (interface
only); scanned PDFs return empty text and are counted in stats.
Done when: bench corpora with PDF attachments (bench B1 will emit them)
index and answer category 1 questions; cache invalidates on tool version
bump.

### 2.2 Embedder adapters
Ship two reference Embedder implementations in src/embedders/ (exported
via a subpath, dependencies optional): local transformers.js
(all-MiniLM-L6-v2 class model) and a generic OpenAI-compatible HTTP
adapter with batching, retry, and rate limiting. Embedding writes already
key by model; add `reembed(model)` to the facade so switching models does
not require full reindex.
Done when: e2e can run with the local embedder behind an env flag and
hybrid beats FTS-only on at least one fixture question retrieval rank
(record the comparison in the test as informational output, not a hard
assert).

### 2.3 LLM contextualizer with cache
The Contextualizer interface exists; ship an implementation that calls a
caller-supplied `complete(prompt) => Promise<string>` function (no vendor
SDK dependency), with the cache keyed (chunk id, tool, tool version) in
a new `context_cache` table so reindex does not re-pay LLM cost (chunk
ids are stable across reindex per invariant 3, and context is a
per-chunk artifact, so chunk-level keys are the correct granularity).
Deterministic default remains the fallback and the test path.
Done when: reindex with a mock complete() hits cache 100% on second run.

### 2.4 Near-duplicate suppression
Quoted-reply duplication puts the same paragraph in many chunks. At
search time, collapse candidates whose normalized text is near-identical
(simhash or shingle Jaccard over tokens), keeping the earliest message's
chunk and folding later ones into a `duplicates` list on the SearchHit.
Must remain deterministic.
Done when: a thread where the same sentence is quoted 4 times returns one
primary hit, and bench category 1 accuracy does not regress.

### 2.5 Thread-context expansion
Add `expand: "thread" | "none"` to hybridSearch options: when "thread",
each hit carries the surrounding new-fragment text of its thread
(bounded, e.g. 2 messages each side) for agents that want context without
a second tool call. Parent-document retrieval is a verified win; this is
the email-shaped version of it.
Done when: option exists, bounded, tested, documented in spec 3.6.

## Milestone 3: the memory layer earns its name

### 3.1 Fact extraction pipeline (optional module, LLM-in-the-loop)
A batch job (not in the ingest path): iterate threads, feed new-fragment
text to a caller-supplied complete() with a fixed extraction prompt,
validate proposed facts (entity must resolve, validFrom must parse,
source chunk must contain the value string), and backfill in event-time
order. Facts that fail validation are logged, never asserted. This is
the bench category 3 to 5 play and the riskiest quality surface: keep it
strictly optional and auditable (every assert carries its source chunk).
Done when: on the bench fixture, extraction + asOf answers the temporal
questions that the e2e currently answers with hand-written regexes, at
equal accuracy, behind a flag.

### 3.2 Entity resolution v2
Deterministic upgrades first (bench category 5): domain equivalence
(same registrable domain implies same party unless overridden), display
name matching across addresses with confirmation state
(suggested/confirmed), person move detection (same person, new domain,
overlapping threads). Suggestions surface via a new tool
`suggestParties()`; nothing auto-merges.
Done when: bench B1 category 5 fixture questions are answerable after
confirming suggestions.

### 3.3 Bench numbers and ablation
When papertrail-bench B1 lands its harness, write the Docket adapter
(ingest corpus, answer(question) over the tools, emit citations), run
the internal baselines (FTS-only, vector-only, hybrid, hybrid+rerank,
with and without contextual prefixes, with and without the fact ledger)
and commit the ablation table to docs/ablations.md. This table is the
public launch artifact for the engine.
Done when: numbers are reproducible from a script with pinned seeds.

## Milestone 4: nice-to-have, do not start before M1 to M3 are done

- Postgres backend behind the same interfaces (tsvector + pgvector).
- IMAP/Gmail incremental sync example app (examples/, not core).
- Cross-encoder rerank option (local, transformers.js).
- Retention policies (auto-tombstone by age/party, dry-run mode).
- Read-only web viewer for threads and citations (separate package).

## Explicitly still out of scope

Knowledge graphs, multi-tenant cloud service, extract-and-compress
memory, agent frameworks. Docket stays an embeddable engine.

## Task claiming convention

Before starting a task, check STATUS.md for an in-progress note; add one
line there when you begin (task id, date) and move it to the done list
with a summary when finished. Keep spec.md, this plan, and STATUS.md
consistent as work lands: a task is not done while any of the three
contradicts the code.
